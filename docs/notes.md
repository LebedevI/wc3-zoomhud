# Технические заметки

Всё ниже проверено на `Warcraft III 1.27b`, `Game.dll` 14 837 224 байт (1.27.1.7085), Windows 10 x64.

## Адреса в Game.dll

| RVA | Что это | Проверка |
|---|---|---|
| `0x211E00` | `void f(int field, float* value, float* time)` — установка поля камеры, `field = 0` — дистанция | пролог `55 8B EC 33 D2`; вызов из игры/скриптов карт; вне матча даёт исключение |
| `0xD46118` | корень цепочки состояния игры | см. ниже |
| `0xD3D3EC` | байт-флаг «зум уже применён на карте» (использовался в ранних версиях) | сбрасывается при загрузке карты |

### Состояние игры

```
Game.dll+0xD46118 -> +0x34 -> +0x10 -> +0x08 -> +0x278
```

| Значение | Состояние |
|---|---|
| `4` | идёт матч |
| `6` | пауза (меню F10) |
| `0…3` | меню, загрузка, экран итогов |

Значение `6` важно не путать с выходом: иначе таймер и «применённый зум» будут сбрасываться на каждой
паузе.

## D3D9

* Устройство игра создаёт **до** загрузки модификации, поэтому перехват `Direct3DCreate9` и правка IAT
  бесполезны.
* Рабочий путь — создать своё устройство `Direct3DCreate9Ex` + `CreateDeviceEx` (dummy-окно 8×8,
  `D3DFMT_X8R8G8B8`), взять из него `vtable[42]` — это `EndScene`, общая функция для всех устройств.
* В `d3d9.dll` эта функция — **7-байтный thunk** (`push imm8; mov eax, imm32; …`). Обычный 5-байтный
  inline-хук разрезает инструкцию `mov eax, imm32` и ломает всё; нужен вариант на 7 байт с трамплином.
* Рисование: `GetBackBuffer(0,0,D3DBACKBUFFER_TYPE_MONO)` → `GetDC` → `TextOutA` → `ReleaseDC`,
  всё в `__try/__except`, чтобы HUD никогда не ронял игру.

## Ввод

* `GetAsyncKeyState` работает глобально, поэтому клавиши видны и без фокуса — но **игра их тоже видит**:
  PageUp/PageDown в 1.27 прокручивают камеру, Insert/Delete — поворачивают. Из-за этого зум «уезжал»:
  мод менял дистанцию, а игра тем же нажатием сдвигала цель камеры.
* Решение — `WH_KEYBOARD_LL` в отдельном потоке с циклом сообщений: хук сам считает нажатия и
  возвращает `1` (съедает). Ставить хук только когда `GetForegroundWindow()` принадлежит нашему процессу,
  иначе PageUp перестанет работать в других программах.
* После перехвата `GetAsyncKeyState` этих клавиш **не видит** — хоткеи обрабатываются по счётчикам из хука.

## Пинг

* `GetExtendedUdpTable` удалённый адрес не отдаёт — для UDP-игр (LAN) адрес пира системе неизвестен.
* Рабочая схема: `GetExtendedTcpTable` (ESTABLISHED) → адрес пира → `IcmpSendEcho` в отдельном потоке,
  иначе адрес из конфига. Сверка с системным `ping`: расхождение 0–2 мс.

## Форматирование

`wsprintfA` / `wvsprintfA` **не поддерживают `%f`** — только целые. При `%.0f` в HUD выводится мусор
из одного символа; кастовать во `int` и собирать дробную часть вручную.

## Корректный выход

При выгрузке процесса игра ещё раз вызывает захуканные функции. Если DLL уже выгружена, а `jmp`-хуки
в `Game.dll`/`d3d9.dll` остались — получаем `ACCESS_VIOLATION` (нефатальный: его ловит BlizzardError и
показывает окно с GUID). Поэтому в `DLL_PROCESS_DETACH`:

1. поднять флаг завершения, чтобы потоки вышли;
2. снять хук клавиатуры;
3. **вернуть исходные байты** захуканных функций (`remove_hooks()`).

Признак этой проблемы в отчёте Blizzard: нашего модуля **нет в списке загруженных**, хотя он был загружен.
Отчёты лежат в `%LOCALAPPDATA%\Temp\BlizzardError\<дата>\Crash.txt`.

## Лимит FPS

В 1.27 презентация идёт с `D3DPRESENT_INTERVAL_IMMEDIATE` (vsync выключен), но игра всё равно держит
~64 FPS. Покадрового `Sleep` нет, `timeBeginPeriod(1)` не помогает, `timeGetTime` в `Game.dll` не
вызывается. То есть ограничитель зашит в сам цикл кадров; для снятия нужен отдельный разбор этого цикла.
Строка `maxfps` в `Game.dll` — метрика телеметрии, не настройка.
